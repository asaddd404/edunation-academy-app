# Что делать, когда сайт лёг

Короткий документ на случай, когда времени читать нет. Команды выполняются
на сервере, в каталоге `/opt/edunation`, если не сказано иное.

Дальше везде используется сокращение:

```bash
alias dc='docker compose -f docker-compose.prod.yml --env-file .env.prod'
```

---

## 1. Понять, что происходит (2 минуты)

```bash
dc ps                     # какие контейнеры живы
dc stats --no-stream      # кто съел CPU и память
df -h                     # диск: HLS-видео заполняет его быстрее всего
dc logs backend --tail 100
```

Три типичные картины:

| Что видно | Что это скорее всего |
|---|---|
| CPU 100% у `backend`, память в норме | Импорт PDF или транскодирование видео |
| Память у `postgres` растёт, много соединений | Зависшие запросы или утечка соединений |
| Оба контейнера спокойны, но сайт не отвечает | Забит канал или Caddy держит соединения (L7/Slowloris) |

Топ IP по запросам:

```bash
dc logs web --since 15m | grep -oE '"remote_ip":"[^"]+"' | sort | uniq -c | sort -rn | head -20
```

Активность в базе — что именно выполняется прямо сейчас:

```bash
dc exec postgres psql -U edunation -c \
  "SELECT pid, state, now()-query_start AS age, left(query,80) FROM pg_stat_activity WHERE state <> 'idle' ORDER BY age DESC LIMIT 10;"
```

---

## 2. Сбросить нагрузку

**Отключить импорт PDF** — самая дорогая операция в приложении
(10.6 с CPU на 400-страничный файл). Остальной сайт продолжает работать:

```bash
echo 'ENT_PDF_IMPORT_ENABLED=false' >> .env.prod
dc up -d --no-deps backend
```

Учителя получат 503 с понятным текстом. Вернуть обратно — убрать строку и
повторить команду.

**Убить зависший запрос в базе** (`pid` из запроса выше):

```bash
dc exec postgres psql -U edunation -c "SELECT pg_cancel_backend(<pid>);"
# если не помогло:
dc exec postgres psql -U edunation -c "SELECT pg_terminate_backend(<pid>);"
```

**Заблокировать один IP** на уровне хоста:

```bash
sudo ufw insert 1 deny from <IP> to any
```

---

## 3. Включить внешнюю защиту

Если атака волюметрическая (канал забит, сервер сам по себе не нагружен),
кодом это не решается — только выше по стеку.

1. В панели Cloudflare: **Security → Settings → I'm Under Attack**.
   Одна кнопка, включается за секунды.
2. Если домен ещё не за Cloudflare — это первое, что нужно сделать после
   инцидента (см. раздел «Остаточный риск» ниже).
3. Написать хостеру: у большинства есть фильтрация трафика по запросу.
   Указать: домен, IP `185.129.51.116`, время начала, характер трафика.

---

## 4. Проверить, что восстановилось

```bash
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://edunationacademy.kz/api/v1/../health
dc exec postgres psql -U edunation -c "SELECT count(*) FROM pg_stat_activity;"
```

Главный признак здоровья: **сервис поднялся сам, без перезапуска**. Если
понадобился `dc restart` — где-то течёт ресурс, и это нужно найти, а не
списать на нагрузку.

---

## Остаточный риск

**Домен резолвится напрямую в IP сервера (`185.129.51.116`), CDN/WAF перед
ним нет.** Проверено 2026-08-23: `Server: Caddy` отвечает напрямую. Это
значит, что волюметрическая атака в несколько Гбит/с забьёт канал раньше,
чем хоть один запрос дойдёт до приложения, и **ничто в этом репозитории
этому помешать не может**.

Что с этим делать (порядок важен):

1. Завести домен в Cloudflare, включить проксирование («оранжевое облако»).
2. **Сменить IP сервера.** Старый уже засвечен — он есть в истории DNS и в
   Certificate Transparency (`crt.sh`), и атакующий обойдёт Cloudflare,
   обратившись к нему напрямую.
3. Закрыть файрволом 80/443 для всех, кроме подсетей Cloudflare:
   ```bash
   for net in $(curl -s https://www.cloudflare.com/ips-v4); do
     sudo ufw allow from $net to any port 80,443 proto tcp
   done
   sudo ufw deny 80/tcp && sudo ufw deny 443/tcp
   ```
4. Проверить, что реальный IP больше нигде не светится: поддомены, старые
   A-записи. MX уже указывает на другой хост (`89.35.125.9`) — это верно,
   почта origin не выдаёт.

Пока эти четыре пункта не выполнены, всё остальное в этом документе
защищает только от L7 и от исчерпания ресурсов — то есть от атаки, которая
до сервера дошла.
